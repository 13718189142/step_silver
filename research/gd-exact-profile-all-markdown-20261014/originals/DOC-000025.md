# 接管操作说明与可复制提示词

## 若使用参考链接中的 Pharos

参考页是董彬发布的“Pharos 开源 + 实用指南”，已通过浏览器读到正文。其官方仓库为 [frenzymath/Pharos](https://github.com/frenzymath/Pharos)，当前标注 preview。官方操作指南要求从仓库根目录 ops 会话提交问题和材料，随后由项目 main 会话组织数学研究。[操作指南](https://github.com/frenzymath/Pharos/blob/main/docs/operating-guide.md)

本包是便携材料，不是 Pharos 已创建项目。由新系统 ops 读取材料路径，准备项目的 `PROBLEM.md`；把包放入新项目 `materials/`，将用户研究偏好记入 `expert_guidance/INSTRUCTIONS.md`，再由 main 消化为指导和路线表。具体创建命令及目录以新系统当前安装版本为准，不用把 Danus 的内部运行文件当成 Pharos 配置覆盖过去。

官方流程会在启动研究团队前呈现问题与初始指导。本次只整理资料，没有替你安装新系统或启动其研究。[Pharos README](https://github.com/frenzymath/Pharos)


## 文件传递方式

- 同一台电脑：给新系统核心包的完整目录即可；文件夹内相对链接可直接使用。
- 另一台电脑/服务器：复制或上传 `core.zip` 并解压，再改提示词中的材料路径。
- 需要原始计算、历史完整 finding 或旧证明依赖时：同时传递 `full-evidence.zip`，按 `07_资产索引.csv` 定位。它不需要整体一次性塞进模型上下文。

没有把配置、认证信息、worker 私有记忆或其他项目打包。完整证据包中的脚本和预算用于来源复查，运行前需要新系统自行判断依赖与资源边界。
